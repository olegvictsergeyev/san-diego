# San Diego Agent

Агент для Roblox-игры **San Diego**. Отправляет статусы игровых аккаунтов на сервис и выполняет команды от сервера.

## Структура

```
san-diego/
├── final/
│   └── agent.lua           # готовый скрипт для запуска в executor'е
├── modules/
│   ├── http_client.lua     # HTTP-клиент с fallback'ами для разных executor'ов
│   ├── state_collector.lua # сбор состояния персонажа
│   ├── command_engine.lua  # движок команд + отмена
│   ├── result_store.lua    # хранение неотправленных результатов команд
│   └── agent.lua           # основной цикл агента
├── test/
│   └── agent-standalone.lua # локальная отладка без raw-URL, всё в одном файле
├── docs/
│   └── agent-commands-api-prompt.md  # промт для другого агента (backend API)
└── README.md
```

## Быстрый старт

1. Создайте игру и tracked-поля:
   ```bash
   POST /games { "name": "San Diego", "slug": "san-diego" }
   POST /games/{id}/fields { "name": "position_x", "field_type": "number" }
   POST /games/{id}/fields { "name": "position_y", "field_type": "number" }
   POST /games/{id}/fields { "name": "position_z", "field_type": "number" }
   POST /games/{id}/fields { "name": "team", "field_type": "string" }
   POST /games/{id}/fields { "name": "balance", "field_type": "number" }
   ```

   Формат `POST /game/update`:
   ```json
   {
     "nickname": "PlayerOne",
     "game_slug": "san-diego",
     "server_id": "...",
     "place_id": "...",
     "status": "idle",
     "version": "1.0.0",
     "custom_data": {
       "position_x": 123.5,
       "position_y": 10.0,
       "position_z": -45.2,
       "team": "Civilian",
       "balance": 1250,
       "current_command": "move_x",
       "command_started_at": "2026-08-27T15:30:00+03:00",
       "district": "OldTown",
       "poi": "BlackMarket",
       "poi_dist": 210
     }
   }
   ```

2. Замените в `final/agent.lua` URL модулей на свои raw-ссылки с GitHub:
   ```lua
   moduleUrls = {
       http_client = "https://raw.githubusercontent.com/YOUR_USER/san-diego/main/modules/http_client.lua",
       ...
   }
   ```

3. При необходимости измените `balancePath` — путь к балансу в `LocalPlayer`.

4. Запустите `final/agent.lua` в Roblox-executor'е.

5. Для остановки выполните в консоли:
   ```lua
   getgenv().StopSanDiegoAgent = true
   ```

## Локальное тестирование

Для отладки без публикации в git и без реального сервера используйте `test/agent-standalone.lua`:

- Все модули встроены в один файл — не требует `readfile`/`require`.
- `useMockHttp = true` — HTTP-запросы печатаются в консоль, команды берутся из встроенной очереди.
- В очередь можно добавлять свои команды через `http:enqueueCommand("move_x", { value = 10 })`.

## Команды

Агент поддерживает:
- `get_commands` — вернуть список доступных команд и их параметры.
- `move_x`, `move_y`, `move_z` — сместить персонажа по оси. Опциональный параметр `speed` (1..10, по умолчанию 10) задаёт скорость: 10 — максимальная безопасная (32 ст/с, лимит анти-чита), 1 — в 10 раз медленнее. У X/Z-перемещений защита от препятствий: луч впереди — вход в стену не выполняется, низкие препятствия (≤12 ст) перешагиваются с подъёмом, склоны и холмы проходятся с прилипанием к земле; при непреодолимой стене — остановка перед ней и ошибка `blocked: <имя>`. `move_y` — вертикаль без защиты, одиночные прыжки >16 ст фиксирует анти-чит.
- `move_to` — переместить персонажа к целевым координатам `x` и `z` (высота Y подстраивается под рельеф). Опциональный параметр `speed` (1..10, по умолчанию 10). Та же защита от препятствий, что у `move_x`/`move_z`, плюс тангенциальный обход: при блоке агент идёт боковыми шагами вдоль препятствия (по стороне со свободным пространством) и возвращается на курс, как только прямой проход к цели открывается; низкие препятствия по-прежнему перешагиваются. Защита от зацикливания и бюджет детура — при невозможности обойти (тупик, замкнутый двор) команда останавливается с `blocked: ... (avoid: ...)`.
- `turn` — повернуть персонажа на абсолютный угол (0..360). Опциональный параметр `speed` (1..10, по умолчанию 10) регулирует скорость: 10 — быстро, 1 — медленно.
- `turn_with_camera` — повернуть персонажа и камеру на абсолютный угол. Опциональный параметр `speed` (0..10, по умолчанию 10) регулирует скорость и время "передачи" управления камерой обратно игроку; `speed=0` — ничего не делать: ни персонаж, ни камера не поворачиваются (успешный no-op).
- `tilt_camera` — наклонить только камеру по вертикали (-80..80 градусов), не поворачивая персонажа. `0` — горизонт, положительные — вверх, отрицательные — вниз. Опциональный параметр `speed` (1..10, по умолчанию 10).
- `pause` — подождать N секунд.
- `respawn` — умереть и возродиться. Команда завершается только когда персонаж полностью готов выполнять новые команды (новый character, живой гуманоид, HumanoidRootPart); таймаут готовности 30 с.
- `transfer_money_via_respawn` — передавать деньги целевому игроке циклически, умирая и воскрешаясь, пока его баланс не достигнет заданной суммы. Перед смертью подбегает к цели.
- `respawn_for_money` — одна итерация той же логики: проверка баланса, подход к цели, respawn, ожидание, финальная проверка. Возвращает `reached`, `before_balance`, `after_balance`, `respawned`.
- `get_inventory` — вернуть инвентарь: предмет в руке (`held`), содержимое рюкзака по именам (`backpack`), сводку по принтерам (`printers_backpack`, `printers_held`, `printers_total`) и уникальные `printer_ids` (атрибут `PersistentToolId`).
- `buy_printer` — купить N Money Printer у витрины. Требует стоять у витрины. Покупка идёт прямым вводом в ProximityPrompt без эмуляции клавиш, каждая покупка проверяется по приросту числа принтеров; при нехватке денег останавливается и возвращает `bought`. Параметр `count` (1..50, по умолчанию 1).
- `pickup_printer` — подобрать расставленные принтеры обратно в инвентарь (своя комната). Нужен фильтр: `printer_id` (MoneyPrinterId модели) или `floating=true` — только «плавающие» (вставшие не на пол, например на шкаф). Подбор проверяется по исчезновению модели. Параметр `max_count` (1..50, по умолчанию 50).
- `pickup_all_printers` — подобрать ВСЕ расставленные принтеры апартамента (все комнаты), без параметров. Персонаж подводится к каждому промпту с ожиданием репликации, неуспех повторяется до 3 раз — срабатывает даже если персонаж стоит на принтере.
- `deploy_printers` — проверить инвентарь и расстановку: если есть принтеры и разложено < 50 — собрать все и разложить заново сеткой по комнате (ряды прижаты к стене напротив двери, шаг 1.4, валидация мебели), затем встать по центру комнаты спиной к двери. Если принтеров нет — просто встать по центру спиной к двери.
- `rent_apartment` — арендовать номер отеля: тот же серверный вызов, что кнопка Purchase Apartment на двери (без нажатия E). Если номер уже арендован (`OwnedApartmentId` у игрока) — покупка не выполняется, возвращается `already_rented`. Персонаж должен стоять у неарендованной парадной двери (до 20 ст). Параметр `apartment_id` (необязательный, 0..10000): конкретный номер; `0` или отсутствует — ближайшая свободная дверь. Требует команды Civilian. Результат: `rented`, `already_rented`, `apartment_id`, `door_distance`.
- `spawn_vehicle` — заспавнить технику с ближайшей VehicleSpawner-площадки (в радиусе 50 ст) без открытия панели и без клавиши E: тот же серверный вызов, что кнопка панели. Параметр `name` (обязательный, строка 1..64) — имя техники как в списке спавнера (`ducati`, `C63DTM`, `911` и т.д.). Сервер сам валидирует доступ и владение; при успехе персонаж садится в технику. Результат: `spawned`, `position`, `spawner_distance`.
- `fly_car` — полёт машины: поднять и держать на высоте, пока не придёт отмена. Параметр `height` (обязательный, 0..10) — градация высоты: 1 ≈ 1 ст над поверхностью (рейкаст), 10 = +10 ст — максимум, разрешённый анти-читом в движении. `height=0` — быстрая посадка (падение + тормоз) и завершение сессии. Требует сидеть в машине.
- `nav_car` — перемещение летающей машины на смещение: параметры `x` и `z` (обязательные, −2000..2000) — расстояние в стадах со знаком направления. По оси Y машина не смещается: летит на текущей высоте (при активной сессии `fly_car` — на её высоте), повторяя рельеф. Скорость фиксированная 20 ст/с. Прерывается `cancel`: движение остановится, при активной сессии `fly_car` машина останется висеть, иначе сессия завершится. Требует сидеть в машине.
- `drive` — наземная езда (мотоцикл/машина). Управление рулением: техника разворачивается носом к курсу (AlignOrientation) и тянется только вдоль продольной оси — z корректируется поворотами руля, бокового скольжения нет. Если техника стоит боком — сначала развернётся к курсу, потом поедет. Параметр `x` (необязательный, −20000..20000) — смещение по X со знаком; торможение резкое с остановкой у цели. Параметр `z` (необязательный) — абсолютная координата полосы, по умолчанию 150.07 (главный проспект); если `z` не передан — выравнивается на полосу и придерживается её. Если `x` не передан — только встать в полосу, не уезжая. Параметр `speed` (необязательный, 0..10) — ограничение скорости по линейной шкале 0..580 ст/с: 10 или отсутствует = полная скорость, 0 = не уезжать, только встать в полосу. В конце — выпрямление по оси дороги и активная остановка. Результат: `travelled`, `vmax`, `target_vmax`, `brake_dist`, `lane_z`, `time` (опционально `t_300`). Ошибки: `blocked: <объект>`, `knock at v=<скорость>`, `stuck/locked` (сильно ослабленный сторож: только в разгоне и пока цель не пройдена; перелёт цели с медленным торможением — не ошибка). При ошибке `result` — JSON `{ "error": "...", "data": { ... } }`. Требует сидеть в транспорте.
- `jump` — подпрыгнуть.
- `hold_key` — нажать и удерживать клавишу. Параметры: `key` (строка, например `"E"`, `"Space"`, `"LeftShift"`) и `duration` (миллисекунды, 0..60000). `duration = 0` — нажать и сразу отпустить.
- `join_private_server` — перейти на приватный сервер по коду.
- `cancel` — отменить текущую команду.
- `update_agent` — обновить агента до актуальной версии (штатная остановка и перезапуск загрузчика с GitHub). Опциональный параметр `delay` (0..300 сек, по умолчанию 5). Команда возвращается сразу со статусом `scheduled`; аккаунт ненадолго уходит в offline и возвращается после перезапуска. Позволяет обновить агента на конкретном аккаунте без перезахода в игру.
- `afk` — управление AFK-режимом (`enabled`: `on`/`off`, `interval` в секундах). По умолчанию включён и раз в 5 минут имитирует активность (клик через `VirtualUser` + прыжок), чтобы аккаунт не выкинуло из игры.
- `set_action` — установить произвольный статус действия в `custom_data.action` (например, `"farm"`). Параметры: `action` (строка, до 32 символов, пустая строка сбрасывает) и `except` (строка, опционально) — список команд через запятую, которые не сбрасывают `action`.
- `set_time` — установить один из таймеров `time_1`..`time_5`. Параметры: `name` (имя таймера) и `value` (Unix timestamp, опционально). Без `value` используется текущее время. После `respawn` `time_2` сбрасывается автоматически.
- `get_server_players` — вернуть массив объектов со всеми игроками на текущем сервере. Каждый объект содержит `roblox_name`, `display_name`, `user_id`, `team`, `balance`, `properties` (`beach_houses`, `apartments`) и `money_printers` (только для LocalPlayer).
- `get_player` — вернуть объект с данными об одном игроке. Параметр `identifier` — имя аккаунта, display name или user_id.
- `set_team` — сменить команду (team) персонажа. Параметр `team` — имя команды из `Teams` (например, `"Police"`, `"Civilian"`).

## Дисконнект и ошибки

- При системном ErrorPrompt (в том числе ошибки 277/278) агент отправляет `POST /game/update` со `status = "offline"` и информацией об ошибке в `custom_data.disconnect`.
- Агент **не переподключается автоматически** и не нажимает Reconnect. За переходы между серверами отвечает бэкенд через команды, например `join_private_server`.
- После успешного запуска агента старый `disconnect` сбрасывается.
- Результаты команд сохраняются локально и доставляются на сервер с повторными попытками. Сервер должен обрабатывать повторные `POST /commands/{id}/result` идемпотентно.

## Конфигурация

Все настройки в начале `final/agent.lua`:
- `baseUrl` — URL существующего сервиса.
- `gameSlug` — идентификатор игры (`san-diego`).
- `statusInterval` — интервал проверки изменений статуса в секундах (рекомендуется 5–10). `POST /game/update` отправляется только если данные изменились, при старте агента и принудительно раз в 5 минут.
- `balancePath` — путь к балансу, например `"leaderstats.Cash"`.
- `useRemoteModules` — `true` для загрузки модулей по raw-URL, `false` для локального `require`.
- `afkEnabled` — `true` для включения периодического AFK-действия.
- `afkInterval` — интервал AFK-действия в секундах (по умолчанию 300).

## Правила работы с репозиторием

- Все изменения ведутся в одной ветке `main`.
- `final/` содержит только одобренные скрипты.
- `test/` — для черновиков и экспериментов (создайте при необходимости).
- Модули из `modules/` публикуются в git и подключаются через raw-URL.
- При добавлении новых команд или изменении API обязательно следовать `AGENTS.md`.
